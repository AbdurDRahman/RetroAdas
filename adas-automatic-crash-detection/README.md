# Feature 3 — Automatic Crash Detection (+ pothole reporting)

RetroADAS subsystem that detects a collision or rollover from an IMU and
raises an alarm, and recognises potholes so they can be shared as hazards
(Feature 2). It runs on its **own ESP32 DevKit + MPU-6050**, separate from
the Jetson, so it keeps working during Sentry Mode or while the Jetson
reboots. The Jetson receives events over UART, attaches GPS and talks to
`adas-cloud`.

> New here? Read [`handover.md`](handover.md) (state of the work), then
> [`algorithm.md`](algorithm.md) (the design) and [`evaluation.md`](evaluation.md)
> (the numbers).

## Folder layout

```
src/engine.{h,c}          the detector: one struct, one call per IMU sample (algorithm.md)
src/crash_model.h         fitted score weights — GENERATED by eval/fit_model.py
src/crash_detect.{h,c}    original primitives (tilt filter is reused by the engine)
firmware/retroadas_crash/ Arduino sketch for ESP32 DevKit + MPU-6050 (copies of src/ inside)
firmware/sync_src.py      copies src/*.{c,h} into the sketch folder — run before flashing
jetson/crash_link.py      Jetson side of the UART link (protocol.md)
eval/engine.py            ctypes wrapper: Python drives the compiled C (build/libcrash.dll)
eval/datasets.py          loaders: VZCrash parquet, PVS csv, RoadSens-4M csv
eval/run_eval.py          the benchmark → evaluation.md
eval/fit_model.py         fits crash_model.h on VZCrash train (+ real-road negatives)
eval/sweep_road.py        threshold sweep for the pothole branch
eval/replay.py            real-time replay / ESP32 emulation / $SIM streaming to a real board
eval/own_recording.py     run the engine over your own Sensor Logger phone recording
eval/download_vzcrash.*   dataset download (needs a Hugging Face login)
bench/                    the original Tests 2–4 harness (results.md); kept for history
```

Not in git: `data/` (datasets, ~3 GB), `build/`, `.venv/`.

## Setup (Windows, as used here; Linux/macOS: swap `.venv\Scripts\` for `.venv/bin/`)

Needs `gcc` (MSYS2/MinGW) and Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\pip install numpy pandas pyarrow scikit-learn matplotlib pyserial huggingface_hub
```

### Data

| dataset | what for | how |
|---|---|---|
| VZCrash test split (2 × 494 MB) + 2 train shards (2 × 513 MB) | crash recall, harsh-event FPR, fitting | `hf auth login` once (accept terms on the dataset page), then `bash eval/download_vzcrash.sh --train 2` (`eval/download_vzcrash.py` does the same through huggingface_hub, which stalled on one laptop) |
| PVS, 9 drives (~800 MB) | false alarms per hour on real roads, speed bumps | `data/pvs/pvs{i}_gps_mpu_left.csv`, `_labels.csv`, `_settings_left.csv` from the UFSC share linked on the Kaggle page (direct Seafile links; see `eval/datasets.py`) |
| RoadSens-4M (300 MB) | secondary pothole check | Figshare doi:10.6084/m9.figshare.30341143; unpack the "Combined CSV" RARs into `data/roadsens/x/` |

## Commands

```bash
# compile check (what the firmware compiles)
gcc -std=c99 -Wall -Wextra -c src/engine.c -o NUL

# synthetic self-test of the engine through the harness
.venv\Scripts\python eval\engine.py

# full benchmark → evaluation.md (add --quick for a 3000-events-per-shard VZCrash run)
.venv\Scripts\python eval\run_eval.py

# refit the crash score after changing features (writes src/crash_model.h, rebuilds, syncs firmware)
.venv\Scripts\python eval\fit_model.py

# laptop demo of the whole chain: terminal 1 is the Jetson, terminal 2 is the ESP32
.venv\Scripts\python jetson\crash_link.py --tcp 9000 --gps-fake 40
.venv\Scripts\python eval\replay.py vzcrash --label crash --n 0 --tcp 9000 --countdown 5

# stream a real crash recording into a real ESP32 on COM5 (its buzzer goes off)
.venv\Scripts\python eval\replay.py vzcrash --label crash --n 0 --port COM5
```

`evaluation.md` is reproducible: on the same data the accuracy numbers come
out identical; only the ns/sample timing differs between machines.

## Flashing the ESP32

1. `.venv\Scripts\python firmware\sync_src.py`
2. Arduino IDE 2.x → open `firmware/retroadas_crash/retroadas_crash.ino`, board
   "ESP32 Dev Module", upload.
3. Serial monitor at 115200: `# RetroADAS crash unit, model fit-…, MPU-6050 ok`.
   Wiring is in the sketch header.
